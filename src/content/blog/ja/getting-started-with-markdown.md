Markdown は構造化された HTML に変換できるプレーンテキスト形式です。`.md` ファイルに
いくつかの記号を書くだけで、あらゆるレンダラーが見出し・リスト・表・リンクに変えて
くれます。

2004 年に John Gruber が作りました。20 年後の今では、README・ドキュメント・ブログ・
チャットメッセージ・LLM のプロンプトまで、既定の形式になっています。理由は単純で、
どこにコピーしても壊れず、何もレンダリングしなくても原文がそのまま読めるからです。

## なぜ使うのか

具体的な理由は 3 つです。

1. **差分が読める。** Word ファイルの git diff は役に立ちません。Markdown の差分は
   どの文が変わったのかを正確に示してくれます。
2. **どこでも使える。** GitHub から Notion、ChatGPT まで、すべてが受け付けます。
3. **速く書ける。** ツールバーを探す必要も、マウスを触る必要もありません。手は
   キーボードから離れません。

## 実際に使う構文

10 ルール覚えれば十分仕事になります。

### 見出し

```markdown
# 見出し 1
## 見出し 2
### 見出し 3
```

レベルごとに `#` を 1 つ、その**後ろに半角スペースが必須**です。`#見出し` は多くの
パーサーで単なる文字列として扱われます。

### 強調

```markdown
*斜体*  または  _斜体_
**太字**  または  __太字__
***太字＋斜体***
```

### リスト

```markdown
- 箇条書きの項目
- 別の項目
  - ネストした項目（ダッシュの前に半角スペース 2 つ）

1. 番号付きの項目
2. 2 番目の項目
```

ネストはインデントで決まります。箇条書きは 2 つ、番号付きは 3 つです。間違えると、
先頭に妙な空白が入ったフラットなリストになります。

### リンクと画像

```markdown
[リンク文字列](https://example.com)
![代替テキスト](image.png)
```

違いは先頭の `!` だけです。

### コード

インラインコードはバッククォート 1 つ：`` `npm install` ``。

ブロックはバッククォート 3 つで、**必ず言語を指定**してください：

````markdown
```javascript
const x = 1;
```
````

言語を書かないとシンタックスハイライトが付きません。

### 引用

```markdown
> 引用されたテキスト
> 2 行目
```

### 表

```markdown
| 機能 | 状態 |
| --- | --- |
| エクスポート | 公開済み |
| インポート | ベータ |
```

`---` の行は必須です。どの行がヘッダーなのかをパーサーに伝える役割があります。
配置はコロンで制御します。`:---` が左寄せ、`---:` が右寄せ、`:---:` が中央寄せです。

## 初心者が 1 時間溶かしがちな落とし穴

**ブロック要素の前には空行が必要です。** 次はリストとしてレンダリングされません：

```markdown
テキスト
- 項目 1
- 項目 2
```

段落とリストの間に空行を入れてください。見出し・コードブロック・表も同じです。

**4 つのスペースによるインデントでもコードブロックになります**が、タブとスペースを
混ぜると壊れます。最初からバッククォート 3 つのフェンス記法を使えば問題自体が
発生しません。

**方言が違います。** CommonMark が標準で、GitHub Flavored Markdown（GFM）は表・
タスクリスト・自動リンクを追加しています。脚注に対応しているパーサーもあれば、
数式に対応しているもの、どちらも対応していないものもあります。レンダリングできない
ときは、まず方言を確認してください。

**エスケープ。** アスタリスクをそのまま表示したいときは `\*` と書きます。エスケープが
必要な文字：`\`` `*`` `_`` `{`` `}`` `[`` `]`` `(`` `)`` `#`` `+`` `-`` `.`` `!`

## 次のステップ

[Markdown エディター](/ja/markdown-editor/) を開いて、この記事を貼り付けてみて
ください。入力に合わせて右側のレンダリング結果がリアルタイムに更新されます。

Markdown を使わない人に渡す必要が出たら、変換しましょう。
[Markdown → PDF](/ja/markdown-to-pdf/) は書式を保ったまま共有でき、
[Markdown → HTML](/ja/markdown-to-html/) はそのままホスティングできる単体ページを
出力します。
