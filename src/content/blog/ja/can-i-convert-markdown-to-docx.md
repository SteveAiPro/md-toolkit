短い答え：できます。少し長い答え：できますが、`.docx` が何者なのかを先に理解して
おかないと、望んだ結果にはなりません。

## なぜ見た目より難しいのか

Markdown は概念が 20 個ほどの軽量マークアップ言語です。一方 Word の `.docx` は
OOXML パッケージ、つまり文字通り ZIP ファイルであり、中にはスタイル・番号付け定義・
セクション区切り・埋め込みフォント・図のアンカーを記述した XML が入っています。
この 2 つは形がまったく違います。

コンバーターは形式を翻訳しているのではなく、Markdown には存在しない構造を**ゼロから
捏造**しているのです。見出しはどのフォントか？段落後の間隔は？表の罫線はどこから
来るのか？

だからこそ、粗悪なコンバーターが出力したドキュメントは、Word では開けるものの、
迷子になったプレーンテキストのように見えます。

## 残るもの

| Markdown | Word 側 | 備考 |
| --- | --- | --- |
| `#`–`######` | 見出し 1–6 スタイル | Word 標準スタイルなのでナビゲーションウィンドウが機能する |
| `**太字**` / `*斜体*` | 太字 / 斜体 | インラインで維持される |
| リスト | 段落番号 / 箇条書き | ネスト階層も維持される |
| 表 | 本物の Word の表 | タブ文字で誤魔化したものではない |
| ```` ```コード``` ```` | 等幅フォントの段落 | シンタックスハイライトは不可（Word にその概念がない） |
| リンク | ハイパーリンクフィールド | クリック可能なまま |
| 画像 | 埋め込み画像 | 後述の注意あり |
| `>` 引用 | 左罫線付きのインデント段落 | 近似表現 |

## 失われるもの

**シンタックスハイライト。** テキストを全部画像に置き換えない限り、Word は 1 つの
段落の中に色付きトークンを表現できません。コードブロックは等幅フォントの段落として
出てきます。色付きのコードが欲しければ、HTML か PDF に出力してください。

**数式。** コンバーターが先に KaTeX を画像化しない限り、`$E = mc^2$` はそのまま
ドル記号として到着します。

**カスタム CSS。** Markdown 自体にはスタイルがありませんが、HTML から変換している
場合は `class` とインラインスタイルはすべて捨てられます。見た目はコンバーター次第
です。

**脚注とタスクリスト。** 対応状況はまちまちです。`- [ ]` を本物のチェックボックス
フィールドにするコンバーターもあれば、たいていは文字どおり `[ ]` を出力します。

## 画像を壊す 2 つの問題

画像を参照しているのに出力が空になる場合、原因は必ずこのどちらかです。

**1. Word の画像要素は WebP に対応していません。** OOXML の `ImageRun` が受け付ける
のは PNG・JPEG・GIF・BMP だけです。WebP のバイト列を渡すと、Word は空の枠を表示
します。対策は、いったん canvas にデコードして PNG に再エンコードしてから埋め込む
ことです。

**2. オリジン間画像がキャンバスを汚染します。** `fetch()` でリモート画像を取得する
のは CORS の制限を受け、canvas に描き込んだ時点でキャンバスは「汚染」され、以後の
`toBlob()` はセキュリティエラーを投げます。回避策は `<img crossOrigin="anonymous">`
要素で読み込んでから canvas に描く、つまり fetch 経路を避けることです。ただしこれは
相手サーバーが緩い CORS ヘッダーを返す場合にしか機能しません。

ブラウザー完結のコンバーターの多くはこのどちらにも対処していないため、「画像が
消えた」が苦情の第 1 位になっています。

## ローカル変換 vs サイトへのアップロード

ブラウザー内変換にはプライバシーという実利的な理由があります。ファイルアップロードを
受け付けるオンラインコンバーターは、たとえ一瞬であれ、あなたのドキュメントを他人の
サーバーに保存します。それが未公開の契約書ドラフトや未発表の告知なら、話は別です。

完全に自分のブラウザーで動くコンバーターなら、1 バイトも外に出ません。devtools の
network パネルで確認できます。あなたのテキストを含む POST リクエストは一切ない
はずです。

[Markdown → Word](/ja/markdown-to-word/) を試してみてください。左にテキストを
貼り、右でリアルタイムにプレビューし、ダウンロード時に `.docx` が自分のブラウザー
の中で生成されます。

## 変換前のチェックリスト

- 画像は絶対 URL か data URI を使い、相対パスは避ける
- 可能なら WebP は避ける
- 見出しは `#` 構文を使い、1 行を手動で太字にしない
- 表に `---` の区切り行を入れる
- 送る前に必ず自分で開いて確認する
