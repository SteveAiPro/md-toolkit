README の仕事はひとつです。見知らぬ人を「これは何か」から「使えそうだ」へ、できるだけ
速く連れていくこと。多くの README が失敗するのは、読み手ではなく書き手のために
書かれているからです。

幸い、書式はほぼ解が出ています。機能する構成があり、そこから外れてうまくいくことは
まれです。

## 構成

上から下へ、この順に置きます。

1. **名前と 1 行の説明。** キャッチコピーではありません。何をするものかを、文字どおりに。
2. **スクリーンショットか短い GIF**（目に見える出力があるなら）
3. **インストール。** コピペできるコマンドを 1 つ。
4. **使い方。** 意味のある動作をする最小の例。
5. **設定・API リファレンス**（あるなら）
6. 最後に**貢献方法**と**ライセンス**。

これだけです。入っていないものにも注目してください。プロジェクトの状態、理念の
マニフェスト、ロードマップ、12 行にわたるバッジのテーブル。

## 4 つの失敗

**1. インストールコマンドがない。** 最も多い失敗です。読み手は興味を持ってスクロールし、
始め方を探し、散文の壁と wiki へのリンクを見つけて去ります。最初の 1 画面の中に
フェンスブロックでコマンドを置いてください。

**2. 使用例が API の全体像になっている。** README が見せるべきは *hello world* であって、
すべてのオプションではありません。残りはドキュメントサイトか別ファイルへ。使い方の
セクションに目次が必要なら、それは README には長すぎます。

**3. バッジをコンテンツの代わりにする。** 上部のバッジ 6 個が伝えるのは「このプロジェクトは
保守されている」ということだけです。意味のある 2、3 個 — ビルド状態とバージョン —
だけ残して先へ進みましょう。

**4. 古いスクリーンショット。** ないより厄介です。画像撮影時から UI が変わっていると、
読み手は文書全体を疑います。最新に保てないなら、コードブロックを使ってください。

## 効いてくる細部

**コピペが本当に動くようにする。** ここが Markdown 固有の部分です。シェルコマンドは
言語指定つきのフェンスブロックに置きます。

````markdown
```bash
npm install your-package
```
````

行頭に `$` プロンプトを置かないでください。それらしく見えますが、コピペを壊します。
読み手は毎回その周りを選択し直すはめになります。

**ファイルではなくセクションへリンクする。** 見出し ID の自動生成を使えば、
`see [設定](#設定)` のように書けます。アンカーは必ず確認してください。スラッグの
規則はレンダラーごとに異なります。

**オプションには表を使う。** 20 行の散文のオプション一覧は読めません。名前、既定値、
説明の 3 列が正解です。

```markdown
| オプション | 既定値 | 説明 |
| --- | --- | --- |
| `timeout` | `5000` | リクエストのタイムアウト（ミリ秒） |
| `retries` | `3` | 失敗と判断するまでの試行回数 |
```

**長い末尾は折りたたむ。** ネイティブの `<details>` は GitHub で動きます。

```markdown
<details>
<summary>オプション一覧</summary>

...長い内容...

</details>
```

これは Markdown 内の生 HTML です。GitHub とモダンな静的ジェネレーターでは動きますが、
HTML をエスケープするプラットフォームでは動きません。頼る前に読み手を把握してください。

**やらないことを書く。** 短い「非目標」または「制限」のセクションは、issue を減らし、
読み手の無駄な夜を救います。過小評価されている工夫です。

## 長さ

正しい長さはありませんが、正しい**形**はあります。文書の下へ行くほど内容は専門的に
なる、という形です。使い方のセクションで読むのをやめても成功できるようにしておきます。

README が 2 画面を超えるなら、その先の内容はおそらく `docs/` に置くべきです。埋め込む
のではなく、README からリンクしてください。

## README を別の場所で再利用する

README は、あなたが持っている最良の宣伝文句であることが多いものです。覚えておきたい
変換が 2 つあります。

**画像へ。** README を描画したスクリーンショット — 名前、説明、インストールコマンド、
例が 1 枚に収まったもの — は、そこそこのソーシャル投稿になります。長くなりすぎると
読めなくなるので、上部で切り取ってください。[Markdown → 画像](/ja/markdown-to-image/)
は PNG として描画します。

**PDF へ。** Word 中心の人に渡す社内ドキュメントや、リリースと一緒に文書の特定バージョンを
保存しておくのに便利です。[Markdown → PDF](/ja/markdown-to-pdf/) はブラウザーの印刷
エンジンを使うため、コードブロックがページをまたいで適切に改ページされます。真っ二つに
切れることはありません。

## 5 分テスト

プロジェクトを見たことのない人に、README のとおりに進めてもらい、どこで詰まったかを
聞いてください。つまずいた場所が直すべき点です — そしてそれは、あなたが分かりにくいと
思っていた箇所ではないことがほとんどです。

[Markdown エディター](/ja/markdown-editor/) で下書きすれば、書きながら描画結果を
確認できます。README を生の Markdown のまま読むと、読み手がぶつかる問題がちょうど
見えなくなります。
