「JavaScript で HTML を PDF に」と検索すると `html2pdf.js` が見つかります。jsPDF と
html2canvas を束ねたライブラリーです。動きはしますが、ドキュメント相手には道具の
選択を間違えています。その理由と、正しいやり方を説明します。

## ラスタライズの問題

`html2canvas` はページのスクリーンショットを撮っているのではありません。DOM を
走査し、計算済みスタイルを読み取り、各要素を描画コマンドで `<canvas>` に描き直して
います。jsPDF はそのキャンバスを 1 枚のビットマップ画像として PDF に埋め込みます。

結果として：

- **テキストがテキストではない。** ピクセルです。選択も検索もコピーもできません。
- **リンクが死ぬ。** ハイパーリンクは色付きのピクセルになります。
- **サイズが膨らむ。** 10 ページのドキュメントは 10 枚の全面画像になります。
- **改ページは推測。** jsPDF はピクセルの高さから切断位置を計算するため、コード
  ブロックが真っ二つに割れます。
- **長いドキュメントで壊れる。** キャンバスには最大サイズがあり（Chrome は約
  16384px）、超えると白紙ページが出ます。

1 ページの請求書なら問題ありません。30 ページのドキュメントなら、上のすべてが
受け入れがたい欠点になります。

## 別の方法：ブラウザーにやらせる

どのブラウザーにも高品質な PDF ジェネレーターが内蔵されています。印刷エンジンです。
ベクター出力で、改ページをネイティブに処理し、20 年以上磨かれてきました。

手順：

1. 隠し iframe の中で Markdown を HTML にレンダリングする
2. iframe 内で `@media print` のスタイルシートを適用する
3. `contentWindow.print()` を呼ぶ
4. ユーザーが印刷ダイアログで「PDF として保存」を選ぶ

得られるのは、選択可能なテキスト、クリックできるリンク、正しい改ページ、そして
数分の 1 のファイルサイズです。

## 改ページを制御する CSS

ここが本題です。改ページは JavaScript ではなく CSS で指定します：

```css
@page {
  margin: 18mm 16mm;
}

h1, h2, h3, h4 {
  break-after: avoid;   /* 見出しをページ末尾に孤立させない */
}

pre, table, img, figure {
  break-inside: avoid;  /* コードブロックを 2 ページに分割しない */
}

p {
  orphans: 3;           /* ページ末尾に最低 3 行残す */
  widows: 3;            /* ページ先頭に最低 3 行送る */
}
```

`pre` に `break-inside: avoid` を付けるだけで、PDF 生成で最も多い不満が解消します。

## 印刷では駄目なケース

2 つの状況では本物の PDF ライブラリーが必要です。

**ユーザー操作が許されない場合。** `window.print()` はダイアログを出します。
バックグラウンドタスクや Node スクリプトで PDF を作るなら、`pdf-lib` か Puppeteer を
使うことになります。

**バイト単位で同一の出力が求められる場合。** 印刷ダイアログの設定（余白・ヘッダー
フッター・拡大率）はユーザーのブラウザー次第で、完全には制御できません。どこでも
まったく同じ見た目でなければならない法的文書なら、サーバーサイドでレンダリング
してください。

それ以外、メールで送るドキュメント、共有する仕様書なら、印刷の方が優れています。

## 実践的なコツ

**印刷前にドキュメントタイトルを設定する。** 多くのブラウザーは `<title>` を PDF の
ファイル名の種にします。H1 から抽出したタイトルを入れておけば、`document.pdf` では
なくちゃんとした名前でダウンロードされます。

**画像の読み込みを待つ。** Markdown がリモート画像を参照している場合、`print()` の
時点でまだ読み込まれていないことがあります。全画像の load を待ってから印刷して
ください。ヘッドレスブラウザーで駆動するなら `page.waitForLoadState` を使います。

**複数ブラウザーでテストする。** Chrome・Firefox・Safari では印刷 CSS の実装に細かい
差があります。Safari は特に `break-inside` に厳格です。

**必要なら明示的に改ページする。** `break-after: page` を指定した
`<div class="page-break">` を置けば、好きな位置で強制的に改ページできます。

印刷方式の実際の挙動は [Markdown → PDF](/ja/markdown-to-pdf/) で確認できます。
表だけを印刷したい場合は [表 → PDF](/ja/markdown-table-to-pdf/) を使ってください。
