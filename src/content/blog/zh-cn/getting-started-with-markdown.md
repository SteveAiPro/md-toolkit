Markdown 是一种纯文本格式，可以被渲染成结构化的 HTML。你在 `.md` 文件里用几个
标点符号写东西，任何渲染器都能把它变成标题、列表、表格和链接。

它 2004 年由 John Gruber 创造。二十年后，它成了 README、文档、博客、聊天消息和
大模型提示词的默认格式。原因很简单：它复制到哪儿都不会坏，而且即使没有任何东西
渲染它，原文依然是能读的。

## 为什么要用它

三个实在的理由：

1. **方便对比差异。** Word 文件的 git diff 完全没法看。Markdown 的 diff 能精确告诉你
   哪一句话改了。
2. **到处都能用。** 从 GitHub 到 Notion 到 ChatGPT，全都认它。
3. **写得快。** 不用找工具栏，不用动鼠标，手不离键盘。

## 真正会用到的语法

掌握十条规则就够用了。

### 标题

```markdown
# 一级标题
## 二级标题
### 三级标题
```

一级一个 `#`，后面**必须跟一个空格**。`#标题` 在大多数解析器里会被当成普通文字。

### 强调

```markdown
*斜体*  或  _斜体_
**粗体**  或  __粗体__
***粗斜体***
```

### 列表

```markdown
- 无序项
- 另一项
  - 嵌套项（破折号前空两格）

1. 有序项
2. 第二项
```

嵌套靠缩进。无序空两格，有序空三格。弄错了会得到一串带奇怪前导空格的平级列表。

### 链接和图片

```markdown
[链接文字](https://example.com)
![替代文字](image.png)
```

唯一区别就是开头那个 `!`。

### 代码

行内代码用单个反引号：`` `npm install` ``。

代码块用三个反引号，而且**一定要标注语言**：

````markdown
```javascript
const x = 1;
```
````

不标语言就没有语法高亮。

### 引用

```markdown
> 被引用的文字
> 第二行
```

### 表格

```markdown
| 功能 | 状态 |
| --- | --- |
| 导出 | 已上线 |
| 导入 | 测试中 |
```

`---` 那一行是必须的——它告诉解析器哪一行是表头。对齐方式用冒号控制：
`:---` 左对齐，`---:` 右对齐，`:---:` 居中。

## 几个能坑掉新手一小时的地方

**每个块级元素前面都要有空行。** 下面这个不会渲染成列表：

```markdown
一段文字
- 第一项
- 第二项
```

段落和列表之间必须空一行。标题、代码块、表格同理。

**用四个空格缩进也能表示代码块**，但混用 tab 和空格会坏掉。直接用三个反引号的
栅栏式代码块，彻底绕开这个问题。

**不同方言不一样。** CommonMark 是标准，GitHub 风格（GFM）额外支持表格、任务列表
和自动链接。你的解析器可能支持脚注，也可能支持公式，也可能都不支持。有东西渲染
不出来，第一件事就是查方言。

**转义。** 想显示字面意义的星号，写 `\*`。需要转义的字符：
`\`` `*`` `_`` `{`` `}`` `[`` `]`` `(`` `)`` `#`` `+`` `-`` `.`` `!`
