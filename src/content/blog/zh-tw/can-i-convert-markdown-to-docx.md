簡短回答：能。長一點的回答：能，但你得先搞清楚 `.docx` 到底是什麼，否則結果不會
是你想要的樣子。

## 為什麼這件事比聽起來難

Markdown 是一門輕量標記語言，大概二十個概念。Word 的 `.docx` 是 OOXML 套件——字面
意義上就是個 ZIP 檔案，裡面裝著描述樣式、編號定義、分節符、嵌入字型和圖形錨點的
XML。這兩者形狀完全不同。

轉換器不是在把一種格式翻譯成另一種，它是在**憑空補齊**大量 Markdown 裡根本不存在
的結構：標題用什麼字型？段後間距多少？表格的邊框從哪裡來？

這就是為什麼粗糙的轉換器產出的文件，雖然能在 Word 裡打開，但看起來像一個迷路的
純文字檔案。

## 什麼能保留

| Markdown | 在 Word 裡 | 說明 |
| --- | --- | --- |
| `#`–`######` | 標題 1–6 樣式 | 用的是 Word 內建樣式，導覽窗格能正常運作 |
| `**粗體**` / `*斜體*` | 粗體 / 斜體 | 行內保留 |
| 清單 | 編號 / 項目符號清單 | 巢狀層級保留 |
| 表格 | 真正的 Word 表格 | 不是用定位字元假裝成表格 |
| ```` ```程式碼``` ```` | 等寬字型段落 | 沒有語法標色——Word 沒有這個概念 |
| 連結 | 超連結欄位 | 仍然可以點擊 |
| 圖片 | 嵌入圖片 | 見下面的警告 |
| `>` 引用 | 帶左邊框的縮排段落 | 近似實作 |

## 什麼會掉

**語法高亮。** Word 無法在一個段落裡表示彩色 token，除非把文字整個丟掉換成圖片。
程式碼區塊會以等寬字型的形式出現。需要彩色程式碼的話，匯出成 HTML 或 PDF。

**公式。** 除非轉換器先把 KaTeX 轉譯成圖片，否則 `$E = mc^2$` 到達時就是字面的
美元符號。

**自訂 CSS。** Markdown 本身沒有樣式，但如果你是從 HTML 轉過來，所有 `class` 和
行內樣式都會被丟掉。長什麼樣由轉換器說了算。

**腳註和工作清單。** 支援程度不一。有些轉換器把 `- [ ]` 變成真正的核取方塊欄位，
大多數轉譯成字面的 `[ ]`。

## 兩個會搞壞圖片的問題

如果你的 Markdown 引用了圖片而轉出來是空的，一定是這兩個之一。

**1. Word 的圖片元素不支援 WebP。** OOXML 的 `ImageRun` 只接受 PNG、JPEG、GIF 和
BMP。丟給它一段 WebP 位元組流，Word 就顯示一個空框。解決辦法是先把圖片解碼到
canvas，重新編碼成 PNG 再嵌入。

**2. 跨域圖片會污染畫布。** 用 `fetch()` 取遠端圖片受 CORS 限制，把它畫進 canvas
之後畫布就被「污染」了，之後呼叫 `toBlob()` 會丟出安全性錯誤。繞法是改用
`<img crossOrigin="anonymous">` 元素載入再畫進 canvas，避開 fetch 這條路徑。
但這只在遠端伺服器願意給寬鬆 CORS 標頭時才有效。

大多數瀏覽器端轉換器這兩條一條都沒處理，所以「我的圖片不見了」是排名第一的抱怨。

## 本機轉換 vs 上傳到網站

瀏覽器端轉換有個實實在在的隱私理由：每一個接受檔案上傳的線上轉換器，都把你的
文件存在了別人的伺服器上，哪怕只是短暫的。如果那是份沒公開的合約草稿或者未發布的
公告，這就很要緊。

完全在你自己瀏覽器裡跑的轉換器，一個位元組都不會送出。你可以打開 devtools 看
network 面板驗證——不應該有任何包含你文字的 POST 請求。

試試 [Markdown 轉 Word](/zh-tw/markdown-to-word/)：左邊貼上文字，右邊即時預覽，
點下載時 `.docx` 在你自己的瀏覽器裡生成。

## 轉換前的檢查清單

- 圖片用絕對 URL 或 data URI，不要用相對路徑
- 能避開 WebP 就避開
- 標題用 `#` 語法，不要手動加粗單獨一行
- 表格有 `---` 分隔行
- 發給別人之前，自己先打開看一遍
